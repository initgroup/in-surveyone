# 2026년 설문 초안 참조 패키지

이 디렉터리는 설문 제작기에서 가져와 수정하는 참조 자료이다. 서버 런타임이 특정 기관의 설문을 하드코딩하거나 외부 PDF에 의존하지 않는다. 원본 PDF와 로고 파일은 이 저장소에 복사하지 않았다.

## 과업 목적과 범위

사용자가 제공한 `과업설명.pdf`의 목적은 내부평가제도 및 보수체계의 효율적 운영 방안과 개선사항을 발굴하고, 직원들이 직접 참여하는 객관적인 부(팀) 협력도 조사를 수행하는 것이다. 과업서의 조사 계획은 내부평가·보수체계 표본 400명, 협력도 각 부(팀)별 3명(부·팀장 포함), 2026년 11월 9일부터 16일까지의 모바일 조사이다. 과업서의 표본·기간은 운영계획 참조이며 가져오기 파일에 수신자, 응답, 배포 기간 또는 공개 상태를 포함하지 않았다.

독립 설문 2개를 보존하고, 최신 요청에 따라 내부평가·보수체계 설문 끝에 협력도를 추가한 통합 설계도 제공한다.

| 파일 | 원문 범위 | 원문 응답 문항 | 온라인 보조 문항 | 안내 블록 |
|---|---|---:|---:|---:|
| `komsco-2026-evaluation-pay.json` | `설문지.pdf` 1~8쪽, 내부평가제도 1~24번·보수체계 1~17번 | 41 | 직급·직무대행 여부 1 | 표지 1 |
| `komsco-2026-cooperation.json` | `설문지.pdf` 9~10쪽, 부(팀) 협력도 1~2번 | 2 | 소속 부(팀) 1 | 표지 1 |
| `komsco-2026-combined.json` | 내부평가·보수체계 다음에 협력도 추가, URL 대상 분기 | 43 | 직급·소속 부(팀) 2 | 표지 2 |

두 설문의 원문 응답 문항 합계는 43개이며, 보조 문항을 포함한 합계는 45개이다. 안내 블록은 응답 문항이 아니다. 첫 설문은 14개 섹션, 두 번째 설문은 3개 섹션으로 나누었다.

## 현재 통합 초안과 URL 대상

기존 내부평가·보수체계 프로젝트에 실제 제작기의 설계 가져오기와 저장 기능으로 통합 초안을 반영했다. 원래 14개 섹션·43개 블록을 그대로 두고 협력도 3개 섹션·4개 블록을 뒤에 추가했다. 총 17개 섹션·47개 블록(원문 응답 43, 보조 응답 2, 안내 2)이다. 별도 협력도 프로젝트는 변경하지 않았다. 두 프로젝트 모두 기존 소유자의 초안이며 공개 배포하지 않았다.

| 공개 URL 뒤 구분자 | 표시 범위 |
|---|---|
| 생략 또는 `?audience=evaluation` | 내부평가제도·보수체계 14개 섹션 |
| `?audience=cooperation` | 부(팀) 협력도 3개 섹션 |
| `?audience=all` | 내부평가제도·보수체계 뒤에 협력도를 포함한 전체 17개 섹션 |

이미 `?lang=ko` 등 쿼리가 있으면 `&audience=cooperation`처럼 연결한다. 실제 공개 주소는 확정·배포 시 발급되며 이 표의 구분자는 인증용 비밀값이 아니다. 고객에게 전체 비교를 보여주려면 제작기 미리보기의 ‘전체 설문 · 협력도 포함’을 선택한다.

확정 직후 ‘설문 대상별 URL · 관리’ 목록에 위 3개 주소가 각각 표시됩니다. 기존 확정 설문도 **설문 만들기 → 설문 프로젝트 → 해당 카드의 대상별 URL · 관리**에서 바로 확인할 수 있습니다. 수신자나 발송 채널 입력은 필요하지 않습니다. 주소는 현재 확정 버전의 설정으로 만들고, 일반 재확정에서는 3개 주소가 유지되며 새 URL 발급 때만 함께 교체됩니다.


통합 설계의 `cooperation_01`은 PDF 9쪽처럼 85개 부서를 읽기 전용 범례 박스에 나열하고 번호 입력칸 5개로 응답한다. 번호 옆에 부서명이 표시되며 `1`~`85`를 `dept_001`~`dept_085` 보기 ID로 연결한다. `cooperation_02`는 기존 85개 객관식 복수선택을 유지하며 보기 배열만 3단(`choiceLayout=columns_3`) 예시로 설정했다. 실제 문항 폭과 긴 부서명을 측정하므로 360px·768px 미리보기에서는 한 열, 1280px 미리보기에서는 세 열로 표시된다. 제작기 속성에서 세로·가로·2단·3단·4단으로 변경할 수 있다. 고객이 두 입력 방식을 비교해 결정할 수 있고, 제작기 문항 속성의 ‘복수응답 입력 방식’에서 변경할 수 있다. 두 방식 모두 1~5개, 자기 부서 제외를 적용한다. 별도 협력도 설계는 두 문항 모두 객관식을 유지한다.

360px·768px·1280px, 번호 중복·미등록·자기 부서 제외, 소속 변경 시 제외 항목 해제, URL별 임시 저장 분리, 저장 후 재열기와 미리보기 대상 전환을 확인했다. 테스트 답변은 가상 요청 또는 미리보기에서만 사용하고 실제 응답으로 저장하지 않았다.

## 제작기에서 사용하는 방법

1. 신규 설문이면 프로젝트를 생성하고, 기존 설문에 통합하려면 해당 프로젝트를 연다. 기존 초안은 먼저 내보내 보관한다.
2. 해당 프로젝트의 설문 제작기에서 초안 가져오기 기능으로 원하는 JSON 파일을 선택한다.
3. 가져온 표지, 섹션, 문항, 선택지, 척도, 분기 조건을 제작기에서 검토한다. 표지는 안내 블록의 서식 HTML 편집으로 수정할 수 있다.
4. 일반 초안 저장 기능을 사용하여 현재 프로젝트와 테넌트에 저장한다.
5. 모바일 미리보기에서 아래 검수 항목을 점검하고 의뢰기관 확인 후 확정·배포한다.

이 파일들은 검토용 초안이다. 파일을 보관하거나 가져오는 동작만으로 공개 URL을 발급하거나 배포·발송하지 않는다. 프로젝트 ID, 테넌트 ID, 응답, 인증정보, 배포 slug와 수신자 목록은 들어 있지 않다.

패키지 형식은 다음과 같다. `draft`는 일반 설문 수정 API와 같은 초안 필드를 사용하며, 파일 전체를 DB에 임의 삽입하는 별도 통로가 아니다.

```json
{
  "format": "in-surveyone.draft",
  "formatVersion": 1,
  "draft": {
    "title": "설문 제목",
    "sections": [],
    "settings": {},
    "skin": {}
  }
}
```

## 원문 대조와 구현 규칙

| 내용 | 안정적인 문항 ID | 구현 |
|---|---|---|
| 수용성 1~4 | `performance_01`~`performance_04` | 개별 10점 척도 |
| 타당성 5~8 | `performance_05`~`performance_08` | 개별 10점 척도 |
| 신뢰성 9~12 | `performance_09`~`performance_12` | 개별 10점 척도, 9·12번 설명에 원문 각주 |
| 실용성 13~16 | `performance_13`~`performance_16` | 개별 10점 척도 |
| 만족도 17~19 | `performance_17`~`performance_19` | 척도 2개, 자유의견 1개 |
| 개인평가 20~24 | `performance_20`~`performance_24` | 3급 이상 또는 직무대행에게만 활성화 |
| 보수체계 1~4·8~10 | `pay_01`~`pay_04`, `pay_08`~`pay_10` | 개별 10점 척도 |
| 보수체계 5·6 | `pay_05`, `pay_06` | 1~2개 복수선택 |
| 보수체계 7 | `pay_07` | 정확히 2개 선택 |
| 보수체계 11~14 | `pay_11`~`pay_14` | 단일선택 |
| 보수체계 15·16 | `pay_15`, `pay_16` | 4급 이하에게만 활성화되는 단일선택 |
| 보수체계 17 | `pay_17` | 자유의견 |
| 협력도 1·2 | `cooperation_01`, `cooperation_02` | 검색 가능한 1~5개 복수선택, 자기 부(팀) 제외 |

- 참조 JSON은 원문의 문항·보기 문구와 번호를 유지한다. 실제 통합 설문은 자동 번호를 켜고 직급·소속 확인 문항을 번호에서 제외해 내부평가 1~24, 보수체계 25~41, 협력도 42~43으로 연속 표시한다. 각 대상 전용 URL은 그 대상의 문항만 다시 1번부터 표시한다. 원문 제목과 안정적인 ID는 바꾸지 않는다.
- 원문 번호를 보존하는 참조 JSON에서는 `showQuestionNumbers=false`로 자동 번호를 끄고 원문 제목의 번호를 표시한다. 종이의 표 형식 척도는 모바일에서 한 문항씩 응답할 수 있는 30개의 개별 척도 문항으로 옮겼다. 각 척도는 10(매우 그렇다)부터 1(전혀 그렇지 않다) 순서이고 숫자 응답을 저장하므로 개별 문항 보고서에 대응한다. 30개 척도는 `settings.scaleDisplay=slider`로 숫자 눈금·슬라이더·점수 직접 선택을 제공한다. 문항 속성에서 버튼 방식으로 변경할 수 있으며, 표시 방식을 바꿔도 원문의 10점 범위와 문항·분기 ID를 유지한다.
- PDF 2~3쪽에 걸쳐 나뉜 내부평가단 각주를 9번 설명에 합쳤다. BSC 각주는 12번 설명으로 옮겼고 원문의 `Balanced Scored Card` 표기를 유지했다. PDF 추출 순서와 달리 육안으로 확인한 13~16번 다음 17~19번 순서를 따랐다.
- 내부평가·보수체계 표지의 본문, 인사말, 날짜와 주관 부서 문구를 보존했다. 로고 이미지는 추가하지 않았다. 협력도 표지는 원문 공통 안내를 바탕으로 과업서의 협력도 목적에 맞게 본문을 일부 조정한 신규 분리 표지이다. 원문에 협력도 전용 표지가 별도로 있지는 않다.
- `profile_grade`는 원문에 없는 온라인 분기 보조 문항이다. `grade_3_plus`(3급 이상), `grade_4_below_acting`(4급 이하·직무대행), `grade_4_below`(4급 이하·직무대행 아님)의 세 선택지를 사용한다. 개인평가는 첫째·둘째, 보수체계 15~16번은 둘째·셋째에 활성화된다.
- `profile_department`는 원문의 자기 부서 제외 규칙을 집행하는 온라인 보조 문항이다. 원문 85개 부서 목록을 그대로 사용했고, 협력도 1·2번의 목록과 `dept_001`~`dept_085` ID를 일치시켰다. 선택한 자기 부서 1개가 제외되므로 평가 가능한 부서는 84개이다. 원문 9쪽과 10쪽의 85개 목록이 동일함을 대조했다.
- 닫힌형 문항과 보조 문항은 활성화될 때 필수, 자유의견 2개는 선택 응답으로 설정했다. 원문은 온라인 필수 여부를 지정하지 않아 운영 전 확인한다. `기타`는 원문의 선택지이며 추가 주관식 문항을 만들지 않았다.
- 응답자의 이메일, 이름, 사번과 연락처를 수집하도록 설정하지 않았다. 직급·소속 부서라는 보조 정보는 수집된다. 초안의 익명 설정만으로 운영상 익명성이나 원문 비밀보호 문구가 자동 보장되지는 않으므로 실제 배포·발송 방식과 접근 권한을 검토한다.
- 기본 표시 방식은 모바일 스크롤형이고 표지 HTML은 허용 태그로만 구성했다. 이 두 설문을 만드는 데 사용자 JavaScript나 사용자 CSS는 필요하지 않다.

## 확정 전 확인할 원문 사항

- 보수체계 8~10번은 수준을 묻는 질문이지만 원문의 척도 양 끝 문구는 `매우 그렇다`·`전혀 그렇지 않다`이다. 문구를 임의로 고치지 않았으며 의뢰기관 확인 후 제작기에서 수정한다.
- 협력도 2번 제목의 `부(부)`를 원문대로 보존했다. `부(팀)`으로 교정할지는 의뢰기관과 확인한다.
- 원문은 개인평가 대상을 `3급 이상 및 직무대행`, 보수체계 15~16번 대상을 `4급 이하`로 적었다. 이 초안은 문구 그대로 해석하여 4급 이하 직무대행이 두 대상에 모두 포함되게 했다. 과업서 표본표의 `3급이상(직대포함)` 구분과의 관계를 확인한 뒤 대상 조건을 확정한다.
- 부서 목록은 제공된 설문지의 85개 항목을 사용했다. 조직개편, 응답 대상 기관, 대상자 선정 내역과 조사 기간은 실제 운영 직전에 확인한다.
- 과업서의 전자메일·알림톡 또는 SMS·LMS 안내 발송, 표본 선정, 회귀분석 등 결과 분석 및 보고서 제출은 이 초안 파일이 수행하는 기능이 아니다.

## 검수 항목

- 360px, 태블릿, 데스크톱에서 표지·각주·보기 문구가 잘리지 않고 읽히는지 확인한다.
- 세 가지 직급 선택을 바꾸며 개인평가 5문항과 보수체계 2문항의 활성화·필수 여부를 확인한다.
- 보수체계 5·6번의 3개 선택과 7번의 1개·3개 선택이 거부되는지 확인한다.
- 소속 부서를 선택·변경했을 때 협력도 두 문항에서 자기 부서가 제외되고, 0개 또는 6개 이상 선택 제출이 거부되는지 확인한다.
- 미리보기와 저장 후 재열기에서 표지·조건·선택지 ID·척도 순서가 유지되는지 확인한다.
- 확정된 버전의 문항·각주·조건과 공개 화면이 일치하고 응답 및 보고서가 안정적인 문항 ID로 연결되는지 확인한다.
