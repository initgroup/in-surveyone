# IN-SURVEYONE

IN-SURVEYONE은 인아이티가 독립적으로 개발·운영하는 멀티테넌트 온라인 설문 플랫폼입니다. 기관 회원은 템플릿 또는 문항 제작 도구로 설문을 만들고, 버전을 확정해 고유 URL로 배포하며, 이메일·문자·카카오 알림·QR·홈페이지 삽입 등으로 참여를 안내할 수 있습니다. 응답은 원자료와 재현 가능한 보고서로 관리합니다.

첨부된 기존 서비스 화면과 Google Forms는 기능 흐름을 이해하기 위한 참고 자료입니다. 화면이나 API를 복제하지 않으며 Google API에도 의존하지 않습니다. 이 저장소는 `initgroup-members`, `initgroup-homepage`, `data-editing-system` 등 다른 프로젝트의 파일이나 Python/JavaScript 모듈을 import하지 않는 독립 프로젝트입니다.

## 첫 실행

요구 환경은 Windows PowerShell 5.1 이상과 Python 3.12입니다.

```powershell
.\scripts\setup-venv.ps1
Copy-Item .env.example .env
.\scripts\run-server.ps1
```

로컬 주소는 `http://127.0.0.1:8300`입니다. VS Code에서 `Ctrl+Shift+B`를 누르면 기본 Build Task인 `IN-SURVEYONE: Run Server (8300)`이 실행되고, 프로젝트 `venv`가 활성화된 전용 터미널에 서버가 유지됩니다.

```powershell
.\scripts\validate-source.ps1
```

개발 도구가 필요 없는 운영용 환경만 만들 때는 `setup-venv.ps1 -ProductionOnly`를 사용합니다. `.env.example`에는 안전한 예시와 빈 자격정보만 있으며 실제 `.env`, Oracle 비밀번호, Wallet, 발송 사업자 키는 Git과 백업에서 제외됩니다.

## 탭·바탕화면 아이콘

관리자·공개 설문·오류 화면에 전용 탭 아이콘과 Apple touch 아이콘을 제공합니다. 관리자 홈에는 192/512px 아이콘을 연결한 web manifest도 있습니다. Windows 바탕화면 바로가기는 다음 명령으로 설치합니다.

```powershell
.\scripts\install-desktop-shortcut.ps1
```

공식 주소를 기본 브라우저로 열며, 로컬 개발용은 `-Url http://127.0.0.1:8300/`을 지정합니다. [아이콘 재생성·다른 PC 설치 안내](reference/branding/README.md)를 참고하세요.

## 현재 MVP 구현 범위

현재 소스는 회원가입·로그인, 가입 없는 기능·템플릿 미리보기, 단계형 프로젝트 생성, 관리자 공용 템플릿, 문항/섹션·동적 문항·다국어 편집, 불변 버전 확정, 수신자별 다국어 배포 계획, `/s/{slug}` 모바일 응답, 원자료 조회·CSV, 기본형 집계·Excel/PDF 내보내기와 맞춤형 보고서 레이아웃 초안까지 한 흐름으로 실행할 수 있습니다.

- 이메일·문자·카카오·팩스 계획은 Oracle에 저장하며 현재 실행 API는 `QUEUED`/`DISABLED` 이력까지만 만듭니다. 실제 외부 전송 worker·adapter는 별도 운영 연동 대상입니다.
- M05001 기본형 보고서는 현재 조회한 기준일·응답 상태·배포 버전을 적용해 Excel 집계표와 A4 PDF를 생성합니다. 맞춤형 보고서 레이아웃은 브라우저에 저장하는 Beta이며 서버 영구 저장·실행 이력은 아직 제공하지 않습니다. A4/A3·가로/세로 인쇄와 브라우저 PDF 저장은 사용할 수 있습니다.
- Oracle 모드는 전역 lazy connection pool과 bind SQL repository를 사용합니다. 설정·연결·schema 검증이 실패하면 memory로 조용히 fallback하지 않고 오류를 명시합니다.

## 기술 구조

- Python 3.12, FastAPI, Uvicorn
- 외부 프런트엔드 프레임워크와 번들러를 필수 조건으로 두지 않는 Vanilla HTML/CSS/JavaScript SPA
- REST API와 정적 SPA를 동일 FastAPI 애플리케이션에서 제공
- runtime은 Oracle 저장소만 사용하며 `memory` 저장소는 자동화 테스트 fixture로만 유지
- Oracle thin mode 우선, 필요한 환경에서만 Instant Client/Wallet을 별도 설정
- 반응형 공개 설문, 키보드 접근성, reduced-motion, 모바일 safe area 기본 지원
- 새 설치용 DDL과 기존 설치 업그레이드용 ALT SQL을 함께 관리

```text
in-surveyone/
├─ main.py                    FastAPI 진입점
├─ backend/                   API, 도메인, 저장소, 서비스 계층
├─ database/                  독립 DDL/ALT SQL
├─ frontend/                  SPA HTML, CSS, JavaScript, 이미지
├─ tests/                     API·도메인·저장소 계약 테스트
├─ scripts/                   환경, 실행, 검증, 백업, 명시적 Git 배포
├─ .vscode/                   Python 3.12 및 Ctrl+Shift+B 작업
```

## 핵심 도메인과 URL

데이터 소유권과 배포 안정성은 다음 계층으로 고정합니다.

```text
Tenant(회원사)
└─ SurveyProject(설문 프로젝트)
   ├─ SurveyDraft(편집 중 작업본)
   ├─ SurveyVersion(확정된 불변 스냅샷)
   ├─ SurveyDeployment(공개 기간·활성 버전·스킨)
   ├─ Distribution/Recipient(발송과 수신자)
   ├─ Response(응답, 반드시 수집 당시 버전 참조)
   └─ ReportRun(보고서 실행 조건과 결과 스냅샷)
```

- 모든 업무 레코드는 `tenant_id` 경계를 가지며 서버가 현재 사용자 권한과 함께 검증합니다.
- 프로젝트 초안은 변경할 수 있지만, 배포된 `SurveyVersion`은 수정하지 않습니다. 변경 후 재배포하면 새 버전을 만듭니다.
- 공개 URL은 `/s/{slug}`를 기본 계약으로 사용합니다. 프로젝트 slug는 전체 서비스에서 유일하며 tenant 소유권은 서버가 별도 검증합니다. 예약어·대소문자·길이 규칙도 생성 시 검증합니다.
- 안정적인 공개 URL은 현재 활성 배포 버전을 가리키고, 각 응답은 실제 노출된 `survey_version_id`에 고정됩니다.
- 홈페이지 게시는 공개 URL 링크 또는 접근성 있는 `iframe` embed 코드로 지원합니다. 교차 출처와 frame 정책은 허용된 설문 origin 단위로 제한합니다.
- 공개·종료·일시정지·예약 상태, 시작/종료 시각, 중복 응답 정책, 실명/익명 정책을 배포 설정으로 분리합니다.

## 메뉴와 HTML 파일 규칙

`M` 뒤 두 자리는 대분류, 다음 세 자리는 중분류입니다. 표시 메뉴와 SPA 라우트는 아래 파일 ID를 단일 기준으로 사용합니다.

| 대분류 | 메뉴 ID / HTML | 메뉴 | 역할 |
|---|---|---|---|
| 01 | `M01001.html` | 대시보드 | 작성·진행·종료 현황, 최근 프로젝트, 빠른 시작 |
| 02 | `M02001.html` | 설문 프로젝트 | 목록, STEP 01 기본정보와 대상별 URL 확인·복사·재발급 |
| 02 | `M02002.html` | 템플릿 선택(호환 경로) | 기존 링크를 STEP 04 설문 편집기의 템플릿 레이어로 연결 |
| 02 | `M02004.html` | 응답 UI 선택(내부 단계) | STEP 03 전체 스크롤 또는 한 문항씩 진행, 빠른 스킨 확인 |
| 02 | `M02005.html` | 스킨 설정(내부 단계) | STEP 02 프로젝트별 테마, 로고, 공개 문구와 응답 화면 미리보기 |
| 02 | `M02003.html` | 설문 제작기(내부 단계) | STEP 04 문항·동적 조건 편집, 템플릿 레이어 선택, 저장, 확정 |
| 03 | `M03001.html` | 배포 센터 | 확정 URL을 사용하는 대상자·채널·언어별 안내·발송 작업 |
| 04 | `M04001.html` | 응답 탐색 | 전체 문항 열 기본 조회, 섹션별 열 설정, 응답 상세, 조회 조건의 전체 페이지 XLSX·CSV (보기형·분석형·원본형) |
| 05 | `M05001.html` | 기본형 보고서 | 빈도·교차·기술통계와 표준 차트 |
| 05 | `M05002.html` | 맞춤형 보고서 | 결과 위젯 배치·브라우저 초안 저장·인쇄 |
| 06 | `M06001.html` | 시스템 환경 설정 | IN-SURVEYONE 작업 화면 기본값과 보안 값을 제외한 실행 환경 상태 |
| 07 | `M07001.html` | 공용 템플릿 관리 | 플랫폼 관리자의 템플릿 초안·불변 버전·공개 상태 관리 |

로그인·회원가입·계정 찾기와 공개 응답 화면은 업무 메뉴 ID와 별도의 인증/공개 라우트로 둡니다. 파일을 추가할 때 메뉴 정의, 접근 권한, 제목, breadcrumb, SPA route와 테스트를 함께 변경합니다.

프로젝트처럼 계속 증가하는 업무 데이터는 `select` 콤보박스에 전체 항목을 넣지 않습니다. 검색 가능한 카드·목록과 서버 페이징을 사용하고, 콤보박스는 상태·정렬·언어처럼 값의 수가 작고 안정적인 코드 목록에만 사용합니다. 설문 프로젝트 목록은 한 페이지 24개를 조회하며 검색·상태·정렬 조건도 Oracle 쿼리에 적용합니다. 새 프로젝트와 기존 프로젝트 모두 기본정보 → 스킨 설정 → 응답 UI → 설문 편집의 동일한 STEP 01~04 흐름을 표시합니다. 템플릿은 별도 단계가 아니라 STEP 04의 검색 가능한 카드형 레이어에서 선택하고, 적용 전 구조 교체 범위를 확인합니다.

## 설문 제작

### 템플릿 범주

초기 템플릿 카탈로그는 다음 범주를 포함하고 계속 확장할 수 있습니다.

- 사회조사·시민 인식조사
- 청렴도·이해충돌·조직문화 조사
- 사업체·산업·고용 조사
- 고객·민원·서비스 만족도 조사
- 교육·행사·프로그램 평가
- 내부 임직원·조직 진단
- 신청·등록·사전 수요조사
- 빈 설문과 기관 전용 맞춤 템플릿

템플릿을 선택하면 선택 시점의 불변 템플릿 버전을 소유 프로젝트의 편집 가능한 초안으로 복제합니다. 원본 템플릿의 후속 변경이 회원사의 기존 설문을 바꾸지 않습니다. 편집기에서 STEP 02로 돌아가는 동작만으로는 구조가 바뀌지 않으며, 다른 템플릿 또는 빈 설문을 명시적으로 적용하고 교체 경고를 확인해야 문항·동적 조건·섹션 분기·번역이 교체됩니다. 프로젝트 기본정보·스킨·응답 UI 방식은 유지됩니다.

플랫폼 관리 권한은 tenant의 `OWNER`/`MEMBER` 역할과 분리된 `INIT$SVY_TB_USER.SYSTEM_ADMIN_YN`으로 판정합니다. 회원가입에서 플랫폼 관리자 가입을 선택한 경우에만 서버의 `INIT_ADMIN_KEY`와 제출된 인증키를 상수 시간 비교하고, 일치할 때 `SYSTEM_ADMIN_YN='Y'`로 계정을 생성합니다. 인증키 원문은 사용자·세션·DB에 저장하지 않습니다. 일반 회원가입은 기존처럼 tenant `OWNER`이며 플랫폼 관리 권한은 부여되지 않습니다.

### 문항 유형

- 객관식 단일선택
- 주관식 단답형·장문형
- 복수응답
- 드롭다운
- 5점·7점 등 척도
- 메트릭스/그리드
- 설명용 텍스트·이미지
- 숫자 입력과 단위·범위 검증
- 슬라이더
- 표 입력
- 반복표/반복 그룹
- 날짜·시간·연락처 등 확장 필드

제작기는 섹션, 복제, 버튼·drag 기반 순서 변경, 고정필수·고정선택·동적필수·동적선택 문항, AND/OR 복합 선행조건, 응답 검증, 섹션 분기, 미리보기와 수동 저장·변경 취소를 제공합니다. 동적 조건은 표시 순번이 아니라 안정적인 문항·선택지 ID를 참조하며, 브라우저의 초기 로딩과 `input`/`change` 이벤트 및 서버 제출 검증에서 동일하게 평가합니다. 숨겨진 문항의 위조 응답은 서버가 거부합니다.

설문 제작기는 프로젝트 제목·상태·저장/미리보기/확정 작업과 파일·코드·편집 모드·언어·배포 관리를 두 줄 툴바로 구분합니다. 모든 주요 컨트롤은 44px 높이를 사용하고 불투명 배경으로 문구 겹침을 막습니다. **파일** 메뉴에서 템플릿 선택·설계 불러오기·내보내기를 실행합니다. 문항 도구, 편집 캔버스, 속성 패널은 독립된 작업 영역으로 표시하며 좁은 화면의 보조 명령줄과 문항 도구는 좌우로 스크롤할 수 있습니다. 속성 패널은 실제 툴바 높이에 맞춰 배치합니다. 이 정비는 설문 제작기 화면에 적용하며 저장·확정·URL·DB 계약을 변경하지 않습니다.

설문 제작기는 **수동 저장**을 사용합니다. 입력 이벤트·화면 종료·미리보기는 서버 저장을 실행하지 않습니다. 수정 시 **저장 안 됨**을 표시하고 **저장** 옆의 **변경 취소**로 마지막 조회 또는 마지막 저장 성공 시점의 전체 편집 초안을 복원합니다. 제목·문항·섹션·보기 코드·분기·다국어·스킨/사용자 코드를 함께 되돌리고 서버 소유의 revision·확정 상태·공개 URL은 유지합니다. 복원 기준은 현재 편집 화면 메모리에만 보관하며 브라우저 storage에 업무 초안을 저장하지 않습니다. 저장 중 입력한 추가 수정은 미저장으로 남기고, 저장 실패는 복원 기준을 바꾸지 않습니다. 이동·새로고침은 **저장 후 이동 / 저장 안 하고 이동 / 계속 편집**을 선택합니다. 공용 템플릿의 **저장하고 구조 교체**, 설계 파일의 **불러오고 저장**, **저장·확정**, **저장 후 등록**은 명시적인 저장 작업입니다. 코드·안내문·대상 분기 창의 적용은 편집 초안만 바꾸며 상단 저장이 필요합니다.

문항 편집의 **모두 접기 / 모두 펼치기**와 섹션별 **접기 / 펼치기**로 긴 설문을 정리합니다. 접힌 상태에서도 제목·문항 수·선택 문항 포함 여부를 확인할 수 있습니다. 섹션 이동·선택 문항 복귀·문항 추가 시 해당 섹션이 열립니다. 접기 상태는 현재 화면에서 탭 전환·문항 수정 중 유지하며 설문 저장 내용과 공개 응답에는 영향을 주지 않습니다. 활성 탭은 파란 배경과 흰 글자로 구분합니다.

PC에서는 바깥 페이지 스크롤로 단계 안내를 위로 보내 작업 공간을 넓힐 수 있습니다. 편집기 진입 시에는 작업 영역에 맞춰 이동하고, 바깥 스크롤을 올리면 단계 안내를 다시 확인합니다. 편집기는 별도 화면 전환 없이 공간을 절약하는 단일 레이아웃을 사용합니다. 탭 이동과 창 크기 변경에도 미저장 내용·선택 문항·섹션 접기 상태를 유지합니다.

PC에서는 중앙 본문과 좌우 패널을 각각 스크롤합니다. 중앙 위쪽의 **섹션으로 이동 / 맨 위 / 선택 문항 / 맨 아래**로 긴 설문을 탐색하며, 탭을 바꿨다 돌아오면 본문 스크롤 위치를 유지합니다. 본문 영역에 키보드 포커스를 두면 Page Up/Down·Home/End로 이동할 수 있습니다. 모바일과 작은 태블릿은 페이지 단일 스크롤을 유지합니다. 탐색은 초안을 수정하거나 자동 저장하지 않습니다.

제작기 탭은 작업별로 영역을 나눕니다. **문항 편집**은 문항 도구·설문 소개·개별 속성을, **분기 설계**는 넓은 작업 영역에서 응답별 섹션 이동과 URL 대상·섹션 분기를, **설문 설정**은 응답 정책·언어·프로젝트 스킨을 제공합니다. 문항 전용 양쪽 패널은 분기·설정 탭에서 숨기고 선택 문항과 미저장 입력은 유지합니다.

문항을 선택하면 파란 외곽선과 **편집 중** 안내로 강조합니다. 문항의 **위에 삽입 / 아래에 삽입**을 누르고 유형을 고르면 그 문항 앞·뒤에 추가합니다. 왼쪽 문항 유형은 **한 번 클릭하면 선택만** 합니다. 선택 유형은 파란색으로 표시하고 **더블클릭**, **유형명 추가** 버튼 또는 유형 버튼에서 **Ctrl/Cmd+Enter**를 눌러 문항을 넣습니다. Enter/Space만 누르면 유형만 선택합니다. 왼쪽 문항 도구의 **추가할 위치**에서도 선택 문항 위·아래, 현재 섹션 끝, 설문 맨 끝을 지정할 수 있습니다. **위치 찾기**로 현재 문항을 다시 찾고, 섹션의 **섹션 끝에 추가**에서는 해당 섹션 끝에 넣을 유형을 고릅니다. 맨 아래 **유형명 · 설문 맨 끝에 추가**는 왼쪽의 선택 유형으로 마지막 섹션 끝에 바로 추가합니다. 기존 편집 문항과 위·아래 삽입 위치 설정에 영향을 받지 않습니다. 유형 선택은 초안을 수정하거나 자동 저장하지 않습니다. 자동 문항 번호는 안내문·번호 제외 문항을 빼고 섹션을 넘어 갱신하며 원래 제목의 번호·ID·기존 응답은 바꾸지 않습니다. 제목 편집란은 자동 번호와 겹치지 않게 원래 번호를 제외한 본문을 표시합니다. 추가·수정은 상단 **저장** 전까지 미저장 상태이며 **변경 취소**로 복원할 수 있습니다. **새 섹션**은 즉시 선택됩니다. **섹션 삭제** 확인 창은 포함된 문항·번역·연결된 이동 규칙과 대상 범위의 변경을 안내합니다. 다른 섹션 문항의 조건 참조와 섹션이 없어지는 대상 설정은 먼저 수정해야 하며, 마지막 섹션은 유지합니다. 삭제는 초안에만 적용하고 기존 공개 버전은 재확정할 때 변경합니다.

보기의 **표시 문구**와 **결과 코드**는 별도로 편집합니다. 선택형(객관식·복수응답·목록 선택)과 매트릭스·표·반복표의 행·열은 고유한 `resultCode`를 가지며, 누락된 코드는 편집기에서 자동 생성해 표시합니다. **아래 삽입**, 위·아래 이동과 마지막 추가를 지원하며 순서를 바꾸어도 기존 코드와 안정적인 ID는 바뀌지 않습니다. 결과 코드는 같은 목록에서 중복 없이 1~120자로 지정합니다. 번호 입력형의 `code`는 응답자가 입력하는 양의 정수 번호이며 결과 코드와 구분합니다. 번역 모드에서는 선택형·행·열의 표시 문구만 수정합니다. 보기 배열은 별도의 응답 화면 배열 미리보기에서 확인하며, 분기 조건의 보기 선택도 같은 표시 문구와 결과 코드를 보여주고 내부 연결은 안정적인 ID로 유지합니다.

척도는 실제 숫자 점수와 점수별 표시 문구·결과 코드(`settings.scalePoints`)를 구분합니다. 범위 안의 점수를 편집하며 통계는 실제 숫자 점수로 계산합니다. 숫자·슬라이더는 실제 수치, 문자 문항은 입력한 문자열, 날짜는 YYYY-MM-DD를 저장하고 단위·안내 문구는 응답값에 포함하지 않습니다. 안내 문항은 응답을 저장하지 않습니다. 각 유형의 세부 설정에 저장 기준을 표시합니다.

원자료의 **결과 코드형** CSV·XLSX는 응답 당시 확정 버전의 코드 설정을 해석한 `codedAnswers`를 사용합니다. 단일·복수 선택은 선택 코드, 매트릭스는 행·열 코드, 표·반복표는 코드로 구분한 셀 값을 제공합니다. Oracle과 memory 계약 테스트 모두 같은 변환을 사용합니다. 원본 응답 ID·숫자는 그대로 보존하고 코드 설정은 버전 snapshot에 저장하므로 재확정 후 코드를 바꾸어도 과거 응답은 바뀌지 않습니다. 코드가 없던 과거 버전은 기존 안정적인 ID·숫자를 유지합니다. 이 확장은 기존 JSON 문서에 저장하므로 DB 컬럼 변경이 필요하지 않습니다.

관리자 화면은 브라우저 100% 배율에서 본문 16px, UI 문구·설정 설명 14px, 설정 항목명 15px를 기본으로 사용합니다. 상태 배지와 장식용 구분 문구는 12px로 구별합니다. 공통 글자 크기는 `app.css`의 `--text-body/label/ui/help/meta`로 관리하며 화면 밀도는 여백만 바꾸고 글자를 줄이지 않습니다. 설문 제작기의 문항 제목은 18px 여러 줄 입력란으로 표시하고 내용에 맞춰 높이가 늘어납니다. 세부 설정 입력값은 16px, 설명문은 14px와 넉넉한 줄 간격을 사용하며 속성 패널을 넓혀 긴 문구를 읽기 쉽게 표시합니다. 공개 설문이나 사용자가 직접 지정한 안내문 글자 크기는 해당 설문의 설정을 따릅니다.



### 문서형 설문과 사용자 함수

STEP 04 설문 제작기에서 안내 문항을 추가하고 **안내 서식·표 편집**으로 표지 지문, 제목, 강조, 목록과 표를 작성할 수 있습니다. 안내문 편집기는 자체 호스팅 **Tiptap 3.32.0 (MIT)**을 사용하며 **서식 편집 / HTML 코드** 전환, 제목·굵게·기울임·밑줄·목록·인용·글자 크기·색상·정렬·실행 취소와 표 삽입·행/열 추가·삭제·셀 병합/해제·표 제목 편집을 제공합니다. 모바일 도구 모음은 좌우로 스크롤할 수 있습니다. 표지·안내 표는 검증된 HTML로 저장하며 응답 항목에는 포함되지 않습니다. 일반 입력 문항과 동일하게 순서를 옮기거나 복제하고 다시 편집할 수 있습니다.

같은 창의 **CSS·JavaScript** 탭은 기존 `skin.customCode`를 편집합니다. HTML 탭은 선택한 안내문만 변경하며 설문 공통 HTML·배치 위치를 보존합니다. 공통 코드 적용 스위치는 기존 공통 HTML·CSS·JavaScript 전체의 공개 적용을 제어하고 안내문 HTML은 항상 표시합니다. CSS에서 `[data-notice-id="문항ID"]`로 특정 안내문을 지정할 수 있습니다. JavaScript는 기존 설문 공통 HTML의 격리 영역에서만 실행됩니다. 안내문 미리보기와 공통 코드 미리보기를 분리해 적용 범위를 표시합니다. **변경 적용** 후 상단 **저장**으로 초안을 보관하고, 공개 설문에 반영할 때 다시 확정하세요.

서식은 `data-svy-align`, `data-svy-size`, `data-svy-color`의 제한된 값만 허용하며 화면과 서버가 동일하게 검증합니다. 임의 `style`, 이벤트 속성, 실행 태그는 안내문에 저장하지 않습니다. 원문을 열거나 모드만 전환하면 소스를 변경하지 않으며 실제 서식 편집 시 의미를 보존한 HTML로 직렬화합니다. 라이브러리 원본 빌드·패키지 잠금·설치 안내는 [reference/frontend](reference/frontend/README.md), 배포 번들과 의존 라이선스는 `frontend/vendor/tiptap/`에 둡니다.

- **설계 파일 불러오기 / 내보내기**는 `in-surveyone.draft` 버전 1 JSON을 사용합니다. 가져오기 검토 후 기존 초안 저장 API가 테넌트 권한·현재 revision·문항 계약을 검증합니다. 파일에 포함된 프로젝트 ID나 공개 상태를 적용하지 않습니다.
- **미리보기**는 실제 공개 응답 renderer를 사용합니다. 초안은 격리된 iframe에 전달되며 미리보기 응답은 DB나 브라우저 storage에 저장·제출되지 않습니다. 360px부터 화면 크기를 바꾸어 확인할 수 있습니다. 미리보기는 기본 **100% 원본 크기**로 표시하며, 선택한 해상도를 유지한 채 바깥 영역을 가로·세로로 스크롤할 수 있습니다. 창 크기가 달라져도 자동 축소하지 않습니다. **보기 배율 → 화면 맞춤 · 전체 보기**를 선택하면 전체 화면 구성을 축소해서 확인할 수 있고, 원본 크기로 돌아오면 글자와 입력 요소를 실제 크기로 확인합니다. 배율·해상도 변경 시 미리보기 입력은 유지됩니다.
- 척도 문항 속성의 **척도 응답 방식**에서 `슬라이더 + 숫자 선택`과 `숫자 버튼`을 선택합니다. 새 척도는 슬라이더를 기본으로 만들며, 기존 문항은 저장된 표시 방식을 유지합니다. 5점·10점·0~10점의 숫자 눈금, 선 위의 빈 원 표시와 선택 점수 강조, 큰 양 끝 문구, 점수 직접 선택과 선택 지우기를 제공합니다. 선 위 원과 숫자는 실제 슬라이더 선택 위치에 맞추며, 모바일에서도 높이 56px의 영역을 눌러 선택할 수 있습니다. 양 끝 설명은 `10 · 매우 그렇다`처럼 해당 점수와 함께 선 바로 위에 붙이고, 선택 결과는 눈금 아래에 `선택한 점수 9 / 10`으로 표시합니다. 오름차순/내림차순은 표시 방향만 바꾸고 응답 숫자를 보존합니다.
- 슬라이더는 조작 전까지 미응답이며 기본 위치를 자동 응답으로 저장하지 않습니다. 키보드 방향키·Home·End, 점수 직접 입력/선택을 지원하고 0점도 복원합니다. 숫자 버튼은 모바일에서 줄을 나누어 터치 영역을 확보합니다.
- **자동 문항 번호 표시**는 섹션을 넘어 연속 순번을 부여합니다. 제목 앞의 `1. ` 같은 원문 번호는 화면에서 중복 표시하지 않으며 원문 제목과 문항 ID를 그대로 저장합니다. 문항 속성의 **자동 번호에서 제외**로 직급·소속 확인 문항 등을 순번에서 빼고, 안내문은 항상 제외합니다. 대상별 미리보기와 공개 URL은 해당 대상 문항의 순서를 사용하며 오류 알림도 화면의 같은 번호를 표시합니다.
- 제출 검증 실패 시 첫 오류 문항의 시작과 입력란으로 자동 이동합니다. 하단 오류 알림은 첫 문항과 펼칠 수 있는 전체 오류 목록을 제공하며, 알림 또는 오류 요약의 문항을 클릭하면 해당 입력란으로 이동합니다. 한 문항씩 보기에서는 해당 문항 페이지를 먼저 열고, 매트릭스에서는 첫 미응답 행에 포커스를 둡니다. 반복 제출 시 알림을 중복 쌓지 않고 문항 이동·오류 수정 시 알림을 정리합니다.
- 매트릭스는 문항 안의 실제 가용 폭에 따라 표 또는 행별 카드로 자동 전환합니다. 일반 표는 672px 이상, 8~12열 표는 928px 이상에서 표로 표시하고 13열 이상은 카드로 유지합니다. 같은 입력 요소와 행·열 ID를 사용하므로 화면 회전·크기 변경으로 응답이 사라지지 않습니다.
- 객관식·복수응답 문항 속성의 **보기 배열**에서 세로, 가로 자동 줄바꿈, 2단·3단·4단을 정합니다. `settings.choiceLayout=vertical|horizontal|columns_2|columns_3|columns_4`가 초안과 확정 버전에 저장되며 기존 문항의 기본은 세로입니다. 공통 배열 모듈이 실제 문항 폭, 현재 글꼴과 전체 보기 라벨의 길이를 측정합니다. 지정 단수에 문구를 담기 어렵거나 문항 폭이 480px 미만이면 세로로 전환하고 문구는 줄바꿈하므로 겹치거나 잘리지 않습니다. 가로 배열은 들어갈 수 있는 열 수로 자동 줄바꿈합니다. 화면 크기 변경은 같은 입력 요소의 배치만 바꾸므로 선택값·보기 순서·검색·키보드·보고서 ID를 유지합니다.
- 복수응답의 **입력 방식**을 `보기에서 선택` 또는 `번호 범례 + 번호 입력`으로 정할 수 있습니다. 번호 방식은 전체 보기를 읽기 전용 박스에 표시하고 최대 선택 수만큼 숫자 입력칸(최대 20개)을 제공합니다. 보기의 `code`는 화면 번호, `id`는 응답·분기·보고서 기준이며 번호를 바꿔도 ID는 유지합니다. 없는 번호·중복 번호·선행 응답으로 제외된 항목을 검증하고 입력 번호 옆에 보기 이름을 표시합니다.
- **설정 → URL별 설문 대상 → 대상·섹션 분기 편집**에서 구분자·대상 이름·표시할 섹션·기본 대상을 저장합니다. `/s/{slug}?audience={code}`로 해당 섹션에 응답하며 미지정 URL은 기본 대상을 사용합니다. 선행 조건 문항은 같은 대상에 포함해야 합니다. URL 분기는 대상별 화면 구성용으로, 신원 확인이나 접근 권한을 대신하지 않습니다. 미리보기 상단에서도 대상을 전환할 수 있습니다.
- 대상 설정은 초안과 확정 버전의 `settings.audienceRoutes/defaultAudience`에 함께 저장합니다. 서버는 선택된 대상의 필수 문항만 검증하고 다른 대상의 답변을 거부하며, 응답 metadata의 `audienceCode`를 서버에서 확정합니다. 같은 브라우저 탭의 임시 응답도 대상별로 분리합니다. 기존 JSON 저장 구조를 사용하므로 DDL 변경은 없습니다.

- 긴 보기 목록 검색, 복수응답 최소·최대 개수, 선행 문항에서 선택한 보기 제외를 문항 설정에서 지정합니다. 보기 제외는 화면과 서버가 같은 안정적인 선택지 ID를 사용해 검증합니다.
- 표형 응답은 모바일에서 행별 카드로 표시합니다. 필수 메트릭스는 모든 행의 응답을 검사하고 보고서 API는 행·열별 집계를 제공합니다.

**HTML·CSS·JavaScript** 편집기는 사용자 안내 영역을 추가하고 `SurveyOne.on("load", handler)`, `answerChange`, `pageChange`, `beforeSubmit` 이벤트를 처리합니다. JavaScript는 `allow-scripts`만 허용한 별도 iframe 안에서 실행되며 부모 DOM이나 세션 쿠키에 접근하지 않습니다. HTML은 iframe 안에, CSS는 iframe 및 범위가 제한된 공개 설문 폼에 적용됩니다. 이벤트는 알림으로 제공하며 서버의 필수·분기·제출 검증을 대신하지 않습니다. 함수 오류는 해당 안내 영역에 표시됩니다. `on()`의 반환 함수 또는 `off()`로 이벤트를 해제하며 `getContext()`로 로딩 메타데이터를 확인합니다.

안내 서식, 선택 제한, 사용자 함수는 기존 Oracle `DRAFT_JSON`과 확정 버전 `SNAPSHOT_JSON`에 함께 저장됩니다. DB 컬럼 추가는 필요하지 않으며 이미 확정한 버전에는 소급 반영되지 않습니다. 표지와 일반 설문 문항은 기본 제작 기능을 사용하고, 추가 상호작용이 필요한 부분에 사용자 함수를 적용할 수 있습니다.

이번 과업의 독립 설문 2개 및 URL 분기를 적용한 통합 설계와 원문 대조·사용법은 [참조 설문 안내](reference/surveys/README.md)에 있습니다. 참조 파일은 배포 소스와 분리되며 자동으로 공개하거나 외부 발송하지 않습니다.

### 다국어 설계

- 한 설문의 기본 언어와 사용 언어 목록을 먼저 정하고 한국어(`ko`), 영어(`en`), 일본어(`ja`), 중국어(`zh`), 베트남어(`vi`), 필리핀어(`fil`) 외 BCP 47 언어 코드도 확장할 수 있습니다.
- 설문·섹션·문항·선택지의 안정적인 ID는 언어가 달라도 공유합니다. 번역은 ID와 field 단위로 분리하므로 번역 편집이 분기, 응답, 보고서 열을 바꾸지 않습니다.
- 응답 화면은 `?lang=` 요청값, 브라우저 언어, 설문 기본 언어 순으로 선택하고, 번역이 비어 있으면 기본 언어 원문으로 fallback합니다.
- 배포 버전에는 언어 목록과 번역 snapshot을 함께 고정합니다. 배포 이후 번역을 고치면 새 버전을 만들어 과거 응답의 표시 문구를 재현할 수 있게 합니다.
- 언어 선택기는 키보드와 스크린리더로 조작 가능해야 하며, RTL 언어는 언어 메타데이터의 방향 값을 따릅니다.

Oracle에서는 `INIT$SVY_TB_LANGUAGE`가 언어 카탈로그와 LTR/RTL 방향을, `INIT$SVY_TB_SURVEY_LANG`가 설문별 사용·기본 언어를, `INIT$SVY_TB_SURVEY_I18N`이 버전·resource ID·field별 번역을 보관합니다. `INIT$SVY_FN_I18N_TEXT`는 요청 언어 → 배포 버전에 고정된 기본 언어 → 원문 fallback 순서로 문구를 조회합니다.

## 페이지 도움말

관리 SPA의 각 `Mxxxxx` 페이지에는 현재 페이지의 목적, 시작 순서, 주의점과 관련 기능을 설명하는 `작성 요령` 도움말을 제공합니다. 도움말 버튼은 키보드로 열고 `Escape`로 닫을 수 있어야 하며 닫은 뒤 원래 버튼으로 포커스를 돌려보냅니다. 기본 안내는 프런트엔드 설정에 포함하고, Oracle의 `INIT$SVY_TB_PAGE_HELP`가 제공되면 현재 언어의 운영 도움말을 우선 적용할 수 있습니다.

## 모바일 우선 공개 설문

응답 화면은 관리자 SPA와 별도 shell을 사용하며 360px 모바일을 우선합니다.

- 한 열 흐름, 최소 44px 터치 영역, 모바일 키보드에 맞는 input mode
- 현재 섹션과 진행률, 명확한 이전/다음, safe-area를 반영한 하단 동작
- 네트워크 중단을 고려한 임시저장·재시도와 중복 제출 방지 idempotency key
- 오류 발생 시 첫 오류로 포커스 이동, 문항별 설명과 오류를 `aria-describedby`로 연결
- 스크린리더용 label/fieldset/legend, 키보드 완전 조작, 색상 외 상태 표현
- 공개 전 모바일·태블릿·데스크톱 미리보기와 접근성 점검

## 스킨

설문 스킨은 프로젝트/배포 단위로 적용합니다. 공통 semantic token 위에 로고, 대표색, 표면색, 글꼴, radius, 배경 이미지를 제한된 allowlist로 덮습니다. 관리자 UI의 브랜드와 응답자 스킨을 섞지 않으며, 대비 기준과 모바일 레이아웃을 깨는 값은 저장 단계에서 거부합니다. 사용자 입력 CSS나 실행 스크립트는 허용하지 않습니다.

## 배포와 안내 발송

배포 작업은 확정된 프로젝트만 대상으로 하며 대상자 → 복수 채널·예약 → 언어별 안내문 → 검토·실행 순으로 진행합니다. 수신자마다 국가, 선호 언어, 이메일·휴대전화·카카오 ID·팩스와 복수 허용 채널을 저장하고 `?lang=` 공개 URL을 언어별 안내문에 넣습니다.

- 수신자는 수집 목적과 보유 기간을 명확히 하고 tenant별로 격리합니다.
- 실제 발송은 명시적 provider 설정과 운영 승인이 있을 때만 활성화합니다.
- 메시지 템플릿, 예약 시각, provider message ID, 성공/실패/재시도 상태를 저장합니다.
- 로그에 연락처 본문이나 provider secret을 남기지 않고 화면에서도 마스킹합니다.
- 가입 전에는 기능·템플릿 안내에서 저장 없는 응답 화면 미리보기를 제공합니다.
- 연락처는 `SURVEYONE_DELIVERY_SECRET`으로 암호화하고 별도 HMAC 검색 hash를 저장합니다. 운영에서는 이 값을 안정적인 secret으로 반드시 지정하며 임의 회전하지 않습니다.

## 저장 모드

`.env`의 `DB_MODE`로 Oracle 연결 profile을 선택합니다. `initgroup-members`와 동일하게 `local`은 로컬 Oracle, `cloud`는 Oracle Cloud를 사용합니다. 두 모드 모두 회원·설문·응답을 Oracle에 저장하며 runtime에서 memory repository로 전환하지 않습니다. memory repository는 자동화된 repository 계약 테스트 전용입니다.

| 모드 | 용도 | 특성 |
|---|---|---|
| `local` | 로컬 Oracle 개발 | `DB_USER_LOC`, `DB_PASSWORD_LOC`, host/port/service 사용 |
| `cloud` | Oracle Cloud 및 운영 서비스 | `DB_USER_CLD`, `DB_PASSWORD_CLD`, DSN/Wallet 사용 |

Oracle 연결이나 schema 검증이 실패하면 memory로 조용히 fallback하지 않고 시작을 중단합니다.

Oracle 설정은 공통 `DB_*` 키를 사용합니다. 비밀번호와 Wallet은 `.env` 또는 배포 플랫폼 secret으로만 주입하고 소스·DDL·로그·백업에 넣지 않습니다.

로그인 보안 설정도 공통 `INIT_SECRET_KEY`, `INIT_ALLOWED_ORIGINS`, `INIT_COOKIE_*`, `INIT_SESSION_*`를 사용합니다. 개발 환경에서 `INIT_SECRET_KEY`가 비어 있으면 `runtime/.session-secret`을 최초 한 번 생성하지만, 운영 환경은 Environment Group에 `INIT_SECRET_KEY`를 반드시 등록합니다.

설정 변경 뒤에는 8300 포트 프로세스를 완전히 재시작하고 `/api/health`의 `database.mode`가 `oracle`, schema readiness가 정상인지 확인합니다. 연결 정보·Wallet·필수 `INIT$SVY_` object가 잘못되면 시작을 중단하며 memory로 전환하지 않습니다.

### 운영 환경 필수 키

운영 Git 저장소에는 실제 `.env`나 Wallet을 커밋하지 않습니다. 배포 서비스의 Environment/Secret 설정에는 아래 값을 반드시 등록합니다.

| 키 | 운영 설정 |
|---|---|
| `SURVEYONE_ENV` | `production` |
| `SURVEYONE_BASE_URL` | 실제 HTTPS 서비스 주소 |
| `INIT_ALLOWED_ORIGINS` | 허용할 실제 HTTPS origin. 여러 개면 쉼표로 구분 |
| `INIT_SECRET_KEY` | 배포 서비스가 생성한 충분히 긴 무작위 secret |
| `INIT_ADMIN_KEY` | 플랫폼 관리자 가입 확인용 충분히 긴 무작위 secret. 가입 담당자에게만 별도 전달 |
| `INIT_COOKIE_SECURE` | `Y` |
| `INIT_COOKIE_SAMESITE` | 동일 도메인 서비스는 `lax` |
| `DB_MODE` | `cloud` |
| `DB_USER_CLD` | Oracle 전용 schema 계정 |
| `DB_PASSWORD_CLD` | Oracle 비밀번호 secret |
| `DB_DSN_CLD` | Wallet의 TNS alias 또는 Oracle DSN |
| `DB_ORACLE_MODE` | 기본 권장값 `thin` |
| `DB_WALLET_PATH` | 배포 secret files가 위치한 디렉터리. Render는 보통 `/etc/secrets` |
| `DB_WALLET_PASSWORD` | 해당 Wallet에서 요구할 때만 secret으로 설정 |

로컬 `http://127.0.0.1:8300` 실행에서는 `INIT_COOKIE_SECURE=false`를 사용합니다. Render와 같은 HTTPS 운영 환경에서는 `INIT_COOKIE_SECURE=true`가 필수이며, 애플리케이션은 운영 HTTP 또는 비보안 쿠키 설정을 시작 단계에서 거부합니다.

`SURVEYONE_LOAD_DOTENV=false`는 Render에서 로컬 파일 설정을 읽지 않도록 하는 선택적 방어 설정입니다. `DB_POOL_*`, timeout, rate limit와 발송 provider 키는 `.env.example`의 기본값을 검토해 운영량에 맞게 선택적으로 조정합니다.

Wallet 파일(`tnsnames.ora`, `sqlnet.ora`, `cwallet.sso` 및 Wallet이 요구하는 인증 파일)은 Git이 아니라 배포 서비스의 Secret Files로 제공해야 합니다.

### 카페24 도메인과 Render 연동

카페24 DNS에서 `www.insurveyone.com`을 Render에 연결한 뒤에는 Render의 해당 서비스 Environment에도 공개 주소와 허용 출처를 함께 설정합니다. 서비스 전용 값은 연결된 Environment Group보다 우선합니다.

```text
SURVEYONE_BASE_URL=https://www.insurveyone.com
INIT_ALLOWED_ORIGINS=https://www.insurveyone.com,https://insurveyone.com,https://in-surveyone.onrender.com
INIT_COOKIE_SECURE=true
INIT_COOKIE_SAMESITE=lax
```

`Save and deploy`로 기존 빌드에 설정을 적용합니다. `Save only`는 다음 배포 전까지 실행 중인 서비스에 반영되지 않습니다. 코드를 변경한 경우에는 변경 코드의 배포도 필요합니다.

애플리케이션은 설정된 `SURVEYONE_BASE_URL`의 origin을 허용 목록에 자동 포함하고, CORS와 API 쓰기 요청의 Origin 검증에 같은 목록을 사용합니다. 따라서 공개 주소만 변경하고 이전 Render 주소의 허용 목록을 남겨 두어도 공식 주소의 로그인·저장이 차단되지 않습니다. 추가 접속 주소는 `INIT_ALLOWED_ORIGINS`에 명시합니다. `SURVEYONE_ALLOWED_ORIGINS`는 기존과 같이 `INIT_ALLOWED_ORIGINS`가 없을 때만 사용하는 호환 키입니다. 요청의 Host/프록시 헤더나 임의 하위 도메인으로 허용 출처를 확장하지 않습니다.

추가 서브도메인은 공용 목록을 수정하지 않고 서비스 전용 `SURVEYONE_ADDITIONAL_ALLOWED_ORIGINS`에 쉼표로 등록할 수 있습니다. 아래는 운영자가 소유·관리하며 같은 서비스에 연결할 서브도메인의 예시입니다.

```text
SURVEYONE_ADDITIONAL_ALLOWED_ORIGINS=https://survey.insurveyone.com,https://portal.insurveyone.com
```

최종 허용 목록은 기존 `INIT_ALLOWED_ORIGINS`(없으면 `SURVEYONE_ALLOWED_ORIGINS`) + 공식 `SURVEYONE_BASE_URL`의 origin + `SURVEYONE_ADDITIONAL_ALLOWED_ORIGINS`입니다. 중복은 제거하며 새 설정이 비어 있으면 기존 동작을 유지합니다. `https://`를 포함한 정확한 주소를 입력하고 경로·query·fragment·사용자정보·`*`는 넣지 않습니다. 프로토콜과 포트도 구분하며, 등록하지 않은 다른 서브도메인은 허용되지 않습니다. 해당 서브도메인의 카페24 DNS와 Render Custom Domains 연결을 완료한 뒤, 새 설정을 지원하는 코드를 배포하고 환경설정을 적용합니다. 로컬 환경설정을 변경한 뒤에는 서버를 재시작합니다. 복사할 설정 항목과 현재 공식 도메인 목록은 `.env.example`에도 제공됩니다. 로컬 실행용 `.env`에는 같은 키로 값을 설정합니다. `.env`는 Git 제외 파일이므로 소스로 보존할 설정 기준은 `.env.example`과 이 문서를 함께 유지합니다. Render 운영 값은 서비스 Environment에도 등록합니다.

DNS·HTTPS·화면 조회가 정상이어도 새 도메인의 POST/PATCH가 403 `요청 출처가 허용되지 않았습니다.`이면 DB 호출 전 Origin 차단입니다. `/api/runtime-config`의 `publicBaseUrl`이 공식 주소인지 확인하고, 각 접속 주소에서 로그인·저장·로그아웃을 점검합니다. 쿠키는 접속한 호스트에만 발급되므로 Render 주소와 공식 주소의 로그인 상태는 각각 유지됩니다. 점검 명령과 운영 적용 절차는 [도메인 운영 안내](reference/deployment/README.md)를 참고합니다.

### 도메인별 DB 기능 점검

2026-10-22 공식·Render 주소의 실제 Oracle 업무 검사 54건과 전체 자동화 검사 346개가 통과했습니다. 검사 범위·결과와 남는 제한은 [운영 DB 기능 재검사](reference/deployment/README.md#2026-10-22-운영-db-기능-재검사)에 기록합니다. `/api/health`의 `configured`만으로 DB 저장 성공을 판정하지 않고, 로그인 후 저장·재조회로 확인합니다.

맞춤형 보고서(M05002) 레이아웃 초안과 시스템 환경 설정(M06001)은 현재 브라우저 저장 기능입니다. 접속 도메인별로 분리되어 Render 주소에서 저장한 내용이 공식 www 주소에 자동으로 나타나지 않습니다. 설문·응답·배포 초안은 Oracle에 저장되므로 같은 계정으로 각 도메인에 로그인하면 같은 데이터를 사용합니다.

### QR 공개 주소

배포 센터의 QR은 임의 미리보기 패턴이 아니라 서버가 `qrcode` 라이브러리로 생성한 표준 SVG입니다. 오류 복원 수준 Q와 4모듈 여백을 적용하며, QR에 들어가는 주소는 `SURVEYONE_BASE_URL + /s/{slug}`입니다.

- 현재 공식 주소는 `SURVEYONE_BASE_URL=https://www.insurveyone.com`으로 설정합니다. Render 기본 주소만 사용하는 별도 환경은 해당 환경의 실제 HTTPS origin을 사용합니다.
- `127.0.0.1`과 `localhost`는 휴대폰 자기 자신을 가리키므로 휴대폰 QR 시험에 사용할 수 없습니다.
- 로컬 휴대폰 시험은 `SURVEYONE_HOST=0.0.0.0`, `SURVEYONE_BASE_URL=http://PC-LAN-IP:8300`으로 실행하고 같은 origin을 `INIT_ALLOWED_ORIGINS`에 추가합니다. PC와 휴대폰은 같은 Wi-Fi에 있어야 하며 Windows 방화벽에서 TCP 8300 접근을 허용해야 합니다.
- Git/Render 빌드는 `requirements.txt`의 `qrcode==8.2`를 설치하므로 별도 CDN이나 외부 QR API가 필요하지 않습니다.

## DDL/ALT 정책

현재 기준 파일은 `database/SURVEYONE_SYSTEM_DDL.sql`과 `database/SURVEYONE_SYSTEM_ALT.sql`입니다.

- IN-SURVEYONE이 생성하는 모든 Oracle object는 공유 schema의 다른 제품과 충돌하지 않도록 `INIT$SVY_`로 시작합니다.
- DDL은 빈 스키마에 현재 최종 구조를 생성하는 기준본이며 같은 파일을 다시 실행해도 이미 존재하는 object 때문에 실패하지 않습니다.
- ALT는 기존 schema를 최종 구조로 올리는 idempotent 이력입니다. ALT가 새로 만드는 테이블의 원문과 컬럼 순서는 DDL 기준본과 같습니다. 테이블 컬럼이 변경되는 migration은 Oracle 26ai에서 기존 데이터를 보존한 채 최종 `USER_TAB_COLUMNS.COLUMN_ID` 순서도 DDL과 일치시키고 불일치 시 성공으로 종료하지 않습니다.
- 테이블·컬럼·인덱스·제약조건 변경은 같은 작업에서 DDL 최종본과 ALT 증분을 함께 수정합니다.
- ALT에는 무조건적인 `DROP`, `TRUNCATE`, 데이터 초기화를 넣지 않습니다. 파괴적 변경은 별도 승인·백업·복구 계획이 필요합니다.
- `SURVEYONE_SYSTEM_DROP.sql`은 `INIT$SVY_` object만 제거하고 `SURVEYONE_SYSTEM_TRUC.sql`은 object를 유지한 채 프로젝트 테이블 데이터만 비웁니다. 둘 다 파괴적 관리 스크립트이므로 백업·대상 schema 확인 후 운영자가 명시적으로 실행해야 하며 애플리케이션이나 검증 스크립트가 자동 실행하지 않습니다. 다른 schema의 FK·의존 객체까지 사전 확인하도록 DBA catalog 읽기 권한이 없으면 안전하게 중단합니다.
- tenant/project/version/response/report의 외래키와 tenant 범위 인덱스를 명시합니다.
- Oracle 예약어, 이름 길이, UTC 시각, CLOB/JSON 저장 방식과 대량 응답 조회 계획을 검증합니다.
- SQL 변경 뒤 memory와 Oracle repository 계약 테스트, fresh install과 upgrade 시나리오를 모두 확인합니다.

### 원격 Oracle 적용 순서

애플리케이션 전용 일반 schema로 접속하고(공용 관리자 `SYS`/`SYSTEM` 계정에 만들지 않음) 빈 schema에는 DDL만 실행합니다. 비밀번호를 명령행이나 파일에 적지 말고 SQLcl/SQL*Plus의 비밀번호 prompt 또는 Wallet을 사용합니다.

```text
sql /nolog
CONNECT surveyone_app@service_name
@database/SURVEYONE_SYSTEM_DDL.sql
```

이미 이전 IN-SURVEYONE schema가 있으면 먼저 검증된 백업을 만든 뒤 DDL 대신 `SURVEYONE_SYSTEM_ALT.sql`을 실행합니다. 실행 후 `USER_OBJECTS`, `USER_TABLES`, `USER_TAB_COLUMNS`, `USER_CONSTRAINTS`에서 `INIT$SVY_` object와 invalid object를 확인하고 애플리케이션 health/API smoke test를 수행합니다. `DROP`과 `TRUC`는 설치·upgrade 순서에 포함되지 않습니다.

## 응답과 보고서 재현성

원자료는 수집 당시 설문 버전, 문항 ID, 제출 시각, 응답 상태와 함께 보존합니다. 화면 조회와 다운로드는 tenant/프로젝트 권한, 필터, 열 선택, 개인정보 마스킹을 동일하게 적용합니다.

- 기본형 보고서: 응답 수, 결측, 빈도, 비율, 기술통계, 교차표, 표준 차트
- 맞춤형 보고서: 필터, 파생 지표, 문항 묶음, 표/차트 레이아웃, 설명 문구, 내보내기

모든 `ReportRun`은 `survey_version_id`, 응답 cutoff, 필터 JSON, 지표/레이아웃 정의 버전, 집계 코드 버전, 실행자, 실행 시각과 결과 snapshot/hash를 기록합니다. 같은 입력과 정의로 다시 실행할 수 있어야 하며 보고서 정의 변경은 기존 실행 결과를 덮어쓰지 않습니다. 숫자 산식, 분모, 결측 처리, 다중응답 처리 규칙을 보고서 메타데이터에 표시합니다.

## 기능 안내와 회원 작업공간

비로그인 사용자는 대시보드와 **기능·템플릿 안내(`/#/M01002`)**에서 설계·공개·응답·분석 기능을 살펴보고 분야별 예시를 검색할 수 있습니다. 템플릿 미리보기는 실제 공개 renderer를 격리 iframe에서 실행합니다. 입력은 저장·제출되지 않으며 계정·초안·공개 URL을 생성하지 않습니다. 예시 API `/api/showcase/templates`는 큐레이션 데이터만 읽으므로 Oracle 연결과 무관하게 기능을 설명할 수 있습니다.

실제 설문 작성·저장·확정·URL 발급과 응답·보고서 관리는 로그인 또는 회원가입 후 이용합니다. 기본 로그인은 브라우저 세션 쿠키이며 `로그인 상태 유지`를 선택한 경우에만 영속 쿠키를 발급합니다. 서버 세션은 `INIT_SESSION_TTL_SECONDS`를 따릅니다.

게스트 체험과 발급 API·기존 게스트 로그인·세션·공개 URL은 종료했습니다. 실제 DB 데이터는 사용자가 선택한 **DBA 외래키 확인 후 물리 삭제**를 기다리고 있습니다. 이번 작업에서 DDL/ALT와 기존 호환 컬럼·오브젝트를 파괴하지 않습니다. 확인한 건수, 미실행 상태와 DBA용 점검 SQL은 [게스트 정비 절차](reference/maintenance/README.md)에 기록했습니다.

설문 편집기의 `저장`은 현재 미완성 초안만 Oracle에 보관하며 공개 화면을 바꾸지 않습니다. 작업 순서는 **저장 → 미리보기 → 확정·URL 발급 → 대상별 URL 확인 → 발송 준비**입니다. 미확정 상태에서는 편집기의 `발송 준비`가 비활성화되며 이동 직전 서버에서 확정 URL을 다시 검증합니다. 기존 공개 버전이 있는 경우 발송 준비는 해당 확정 버전을 사용하고 저장한 초안 변경은 재확정해야 공개됩니다. 최초 `저장·확정 및 URL 발급`은 불변 `SurveyVersion`을 생성한 뒤 **대상별 URL 목록을 자동으로 표시**합니다. 배포된 설문에서는 버튼이 `재확정 · 기존 URL 유지`로 바뀌고, 같은 URL로 새 버전을 공개합니다. 이미 열린 응답 화면을 실시간으로 변경하지 않으며 다시 접속할 때 새 버전을 제공합니다.

URL 관리 레이어는 확정본의 제목·기본 언어 제목·대상별 주소만 소유자 범위의 경량 조회로 읽습니다. 과거 확정본에 선택적 번역 제목이나 대상 설정이 없으면 기본 제목·전체 설문 URL을 사용합니다. 편집 초안과 전체 문항을 다시 해석하지 않으며 API 응답에 공식 공개 도메인을 포함해 추가 설정 요청을 줄입니다. 상단 제목·닫기(X)와 하단 `새 URL 발급`·`닫기`는 고정하고 대상 URL 목록만 독립 스크롤합니다. 프로젝트 작업 레이어에서 연속으로 열 때도 이전 닫기 이벤트가 새 창을 지우지 않습니다.

공개 URL의 도메인은 접속한 관리 화면 주소가 아닌 `SURVEYONE_BASE_URL`을 사용합니다. 프로젝트 목록·URL 관리·배포 센터는 서버 설정을 읽으며, 설정 조회 실패 시 접속 주소로 대체하지 않고 다시 불러오도록 안내합니다. 로컬 `.env`와 `.env.example`의 공식 주소 기준은 `https://www.insurveyone.com`입니다. 도메인 변경만으로 slug를 재발급할 필요는 없으며 서버 재시작 후 URL 목록을 다시 열면 새 도메인이 반영됩니다. Render는 로컬 `.env`를 배포하지 않으므로 서비스 Environment의 `SURVEYONE_BASE_URL`도 직접 같은 주소로 변경해야 합니다.

배포 센터는 **문자·카카오 SOLAPI 발송**을 지원합니다. 서버 설정과 최종 확인을 거쳐 실제 발송하며 이메일·팩스는 별도 어댑터가 연결될 때까지 보류됩니다. 비활성 채널은 외부 전송을 시도하지 않습니다. 저장과 확정 등 필수 작업 버튼은 진한 배경·아이콘·굵은 글자로 강조합니다.

URL 관리는 **설문 만들기 → 설문 프로젝트**에 있습니다. 프로젝트 카드의 **대상별 URL · 관리** 버튼이나 편집기의 같은 버튼으로 확정된 대상별 주소를 확인·개별 복사·전체 복사·새 탭 열기할 수 있습니다. 대상자·연락처·발송 채널을 입력할 필요가 없습니다. 대상 3개를 설정한 설문은 `/s/{slug}?audience=evaluation`, `?audience=cooperation`, `?audience=all` 주소 3개를 표시합니다. 대상이 없는 기존 설문은 기본 URL 하나를 표시합니다. 미확정 초안에 대상을 추가해도 공개 URL 목록은 현재 확정 버전의 설정을 유지합니다.

`POST /api/surveys/{id}/publish`는 기존 결과 필드와 함께 `links` 목록을 반환합니다. 권한이 확인된 소유자만 `GET /api/surveys/{id}/public-links`로 현재 확정 버전의 목록을 조회할 수 있습니다. 조회 자체는 설문·버전·배포 초안을 변경하지 않습니다.

URL 관리의 **새 URL 발급**은 `POST /api/surveys/{id}/public-url/regenerate`를 사용합니다. 명시적으로 확인한 뒤 기본 주소를 교체하며, 모든 대상 주소가 같은 새 기본 주소를 사용하고 `audience` 구분자를 유지합니다. 이전 URL과 QR 코드는 즉시 사용할 수 없게 됩니다. 이 동작은 저장된 미확정 문항을 공개하지 않으므로 수정 내용을 반영하려면 먼저 재확정합니다. 일반 재확정은 기본 URL과 모든 대상 URL을 유지합니다.

배포 센터는 **① 대상자 등록 → ② 문안·발송** 두 단계입니다. 카카오의 **템플릿 관리** 창에서 승인 목록 조회·원문 확인·선택 적용을 제공합니다. 기본 문안 3종(참여 요청·재안내·마감 안내)은 편집·복사해 SOLAPI 등록·검수 관리에서 등록할 수 있는 예시입니다. 기본 문안을 골라도 발송 초안의 승인 템플릿을 변경하지 않으며 실제 승인된 기본형을 불러와 선택해야 발송할 수 있습니다. 등록·심사 상태 관리는 SOLAPI 콘솔에서 처리합니다. PC에서는 설문명·단계를 한 도구 모음에 묶고, 설문 상세·복수 채널 설정은 펼쳐도 편집 높이를 줄이지 않는 패널로 제공합니다. 문자·카카오는 휴대폰 형태, 이메일은 메일 형태로 서버의 실제 치환 결과를 표시합니다. 입력 확인·조회 중 상태도 같은 미리보기 영역에서 안내하며 발송 확인·요청은 하단에 유지합니다. 두 번째 화면은 왼쪽에 발신 정보·발송 범위·예약 시각을, 오른쪽에 카카오·문자·이메일 채널과 본문·실제 치환 결과를 배치합니다. **일괄 발송**은 1단계 체크 명단에서 현재 채널 연락처가 있는 사람만 사용하며 발송·제외 인원을 표시합니다. 미리볼 샘플을 바꿔도 발송 명단은 바뀌지 않습니다. **개별 발송**은 등록 명단 검색 또는 직접 입력으로 한 사람과 수신 연락처를 선택하며 일괄 체크 상태를 보존합니다. 직접 입력은 이름과 국내 휴대전화·이메일을 받아 개별 수신자로 적용하고, 일괄 체크는 해제한 상태로 초안 명단에 추가합니다. 적용 전 입력이 남아 있으면 저장·발송을 차단하며 선택 후 기존 서버 미리보기·저장·발송 검증을 동일하게 적용합니다. 이메일은 현재 작성·격리 미리보기·초안 저장만 제공하고 실제 발송 버튼은 미연동으로 안내합니다. 기본은 한 채널이며 복수 채널·우선순위는 펼쳐서 설정합니다. URL 관리 레이어는 경로·입력·스크롤을 보존하며 재발급 후에는 미리보기·동의를 다시 확인합니다.

발송 범위는 기존 `PLAN_JSON.deliveryOptions.sendScope`(`BULK|INDIVIDUAL`)와 `individualRecipientId`에 저장하므로 DDL/ALT 추가 실행은 없습니다. 서버가 미리보기와 대기열 생성에 동일한 범위를 적용하며 개별 수신자 ID는 현재 요청의 명단에서 검증합니다. 기존 범위 설정이 없는 API 계획은 종전 선택 검증을 유지합니다.

M02001의 설문 시작·종료 입력은 접속 브라우저와 Oracle Cloud DB 지역 설정에 관계없이 `Asia/Seoul`(KST, UTC+9)로 해석한 뒤 UTC instant로 저장합니다. 공개 URL의 기간 판정은 애플리케이션 서버의 UTC 시각과 확정 버전에 저장된 UTC instant를 비교하며, 표시만 KST로 변환합니다.

공개 응답 JSON은 의미 데이터 기준 기본 256 KiB(`SURVEYONE_PUBLIC_SUBMIT_MAX_BYTES`), 전송 본문 기준 기본 512 KiB(`SURVEYONE_PUBLIC_BODY_MAX_BYTES`)로 제한합니다. 로그인·가입 본문은 `SURVEYONE_AUTH_BODY_MAX_BYTES`로 JSON 파싱 전에 차단합니다. 서버는 전체 byte 크기뿐 아니라 중첩 깊이, 노드·문자열·컨테이너 수를 검증하고, 재시도는 `Idempotency-Key`로 같은 제출 결과를 재사용합니다.

## 보안·접근성·테스트 기준

- 인증은 세션 수명, Secure/HttpOnly/SameSite cookie와 Origin 기반 CSRF 방어를 적용합니다. 단일 프로세스 방어 한도는 `SURVEYONE_SIGNUP_RATE_LIMIT`, `SURVEYONE_LOGIN_RATE_LIMIT`, `SURVEYONE_RATE_LIMIT_WINDOW_SECONDS`로 조정합니다. 분산 rate limit는 운영 배포 전에 신뢰할 수 있는 proxy IP 설정과 공유 limiter(API gateway/Redis 등)로 추가해야 합니다.
- 모든 API는 object ID만 믿지 않고 tenant와 역할을 다시 검증합니다.
- 공개 제출에는 현재 요청 크기·구조·schema 검증, idempotency와 `SURVEYONE_PUBLIC_SUBMIT_RATE_LIMIT` 단일 프로세스 방어를 적용합니다. 여러 worker에 일관된 IP/device abuse 제한은 운영 edge/shared limiter에서도 적용해야 합니다.
- HTML/리치 텍스트는 allowlist sanitization하며 메시지와 보고서 출력도 escape합니다.
- 연락처, 응답, 다운로드와 보고서 접근은 audit event를 남기되 원문 개인정보를 로그에 기록하지 않습니다.
- WCAG 2.2 AA를 목표로 landmark, heading, label, focus, 대비, 키보드, reduced-motion을 테스트합니다.
- Python domain/API 테스트, memory/Oracle repository 계약 테스트, DDL/ALT 검증, JavaScript 문법, 대표 모바일 viewport와 공개 제출 E2E를 단계적으로 자동화합니다.

## 2026-10-22 화면·업무 흐름 정비

- 공통 코드 편집기는 각 페이지 CSS에 의존하지 않는 적용 스위치, 한글 대응 고정폭 글꼴, 작은 화면 스크롤과 키보드 탭 탐색을 사용합니다. 이벤트 예제는 HTML 표시 영역과 JavaScript를 함께 추가합니다. 불러오기 실패 후 다시 열기·로딩 중 취소·유효하지 않은 코드 미리보기 처리를 검증합니다.
- 스킨·응답 UI·배포·맞춤형 보고서의 미저장 변경은 메뉴 이동·새로고침에서 확인하며 제작기는 저장 후 이동·저장 안 하고 이동·계속 편집을 선택합니다. 저장 실패 시 현재 편집과 마지막 저장 복원 기준을 유지합니다. 스킨 저장도 revision 충돌을 검증합니다.
- 환경 설정은 공통 시작 시 복원되고 모든 메뉴에서 적용됩니다. 시작 화면 선택은 로그인 상태의 메뉴 없는 최초 접속에만 적용하며, 직접 지정한 메뉴 주소를 덮어쓰지 않습니다.
- 맞춤형 보고서는 1% 이하 비율을 100배 확대하던 오류를 수정했습니다. 저장소 오류는 기존 초안을 변경하지 않습니다. 미제공 응답 시간은 `집계 없음`, 일자별 추이 위젯은 `집계 연계 필요`로 표시합니다.
- 스킨 상단 이미지는 저장되지 않는 시험 미리보기입니다. 기관 로고·검색/SNS 공유 정보는 공개 화면 연계 전임을 표시하고 편집을 차단하며 기존 저장 값은 보존합니다. 실제 이메일·문자·카카오·팩스 전송과 맞춤형 보고서 서버 저장은 별도 연계 대상입니다.

`tests/test_frontend_workflow_runtime.py`는 브라우저 환경 설정·저장 실패·비율·공개 글꼴 회귀를 실행합니다. 선택 개발 도구인 Node, Edge, `playwright-core`가 있으면 `SURVEYONE_PLAYWRIGHT_MODULE`에 해당 모듈 경로를 지정한 뒤 `node tests/browser_workflows.cjs`로 추가 검증합니다. 이 검사는 loopback 정적 서버와 합성 API만 사용해 13개 업무 메뉴, 360/768/1440px 편집기, 저장 실패·재시도·PDF 인쇄를 확인하며 운영 계정·DB에 접근하지 않습니다. 생성물은 `.tmp/editor-flow-review/`에 둡니다.

## 검증, 백업, Git 배포

일상 수정은 [변경 영향별 검증 기준](reference/testing/README.md)에 따라 관련 문법·개별 회귀 테스트부터 실행합니다. 문서만 수정하면 문서 검사로 끝내며, 독립 기능마다 전체 pytest와 전체 브라우저 검사를 반복하지 않습니다. 공통 계약의 광범위한 변경·영향 범위 불명확·배포 전에는 전체 검증을 실행합니다. 아래 `validate-source.ps1`은 전체 검증 명령이며 `-SkipTests`도 전체 정적 검사를 수행합니다. 환경 설치와 서버 시작은 필요한 경우에만 실행합니다.

`validate-source.ps1`은 캐시·venv·runtime·생성물 폴더와 reparse point에 진입하기 전에 제외합니다. Python·HTML·테스트 파일 검사는 이 파일 목록을 재사용하며, pytest 캐시를 생성하거나 읽지 않습니다. 제외 대상이 아닌 실제 소스 폴더의 접근 오류는 계속 실패로 보고합니다. `.pytest_cache` 권한을 바꾸거나 삭제할 필요는 없습니다.

```powershell
.\scripts\validate-source.ps1
.\scripts\backup-source.ps1 -Mode Working
.\scripts\backup-source.ps1 -Mode Git
```

백업 위치는 아래 두 폴더의 timestamp 하위로만 제한됩니다.

- `D:\work\backup\in-surveyone_WORKING_BACKUP`

## SOLAPI 문자·카카오 설정과 사용

배포 센터는 상단에 설문명·저장·단계 이동을 두고 본문을 작업 영역으로 사용합니다. PC에서는 대상자 표와 선택 행 상세, 각 단계 본문을 독립 스크롤하며 단계별 본문 위치를 유지합니다. 모바일에서는 페이지 스크롤과 표의 가로 스크롤을 사용합니다. 문안 아래에는 이름·설문 제목·설문 링크·마감일 예약어 범례를 표시합니다. 그 밖의 설명·템플릿 안내는 `?` 도움말로 묶고 키보드·터치로 열며 Esc로 닫습니다. 문안·발송 화면의 도움말은 작업 영역 높이를 줄이지 않는 팝오버로 제공하며 대상·제외 건수, 발송 가능 여부와 오류는 계속 표시합니다. 설문 운영 정보는 접어서 확인하고 발송 이력은 하단에서 조회합니다.

실제 `.env`는 열람·출력·커밋하지 않습니다. 운영 담당자가 `.env.example`의 빈 항목을 참고해 서버 `.env` 또는 서비스 환경변수에 다음 값을 직접 저장한 뒤 서버를 재시작합니다. 인증정보는 브라우저로 전달하지 않습니다.

```dotenv
SOLAPI_API_KEY=
SOLAPI_API_SECRET=
SURVEYONE_SMS_PROVIDER=solapi
SURVEYONE_KAKAO_PROVIDER=solapi
SURVEYONE_SOLAPI_TIMEOUT_SECONDS=20
SURVEYONE_SOLAPI_DEFAULT_SENDER=
SURVEYONE_SOLAPI_KAKAO_PF_ID=
```

키만 저장해도 provider가 `disabled`이면 전송하지 않습니다. 문자만 사용하면 카카오 provider는 `disabled`로 유지하세요. 발신번호는 SOLAPI에서 사전 등록·인증해야 하며 기본 발신번호와 채널 ID는 선택 사항입니다. 배포 작업 STEP 02에서 입력할 수 있습니다. 현재 카카오는 승인된 기본형(BA/NONE) 알림톡을 지원하고 자동 문자 대체는 사용하지 않습니다. 이미지·강조·아이템 등 확장형은 별도 구현이 필요합니다.

1. 확정된 프로젝트의 배포 작업을 엽니다. 모든 단계 제목을 눌러 기능을 미리 볼 수 있으며 단계 이동으로 저장·발송하지 않습니다.
2. STEP 01의 표에서 이름·휴대전화·이메일을 직접 입력하거나 엑셀 셀을 복사해 시작 셀에 붙여넣습니다. 열 제목이 있으면 자동으로 인식하며 별도 구분자·열 연결 화면을 거치지 않습니다. Tab은 다음 셀, Enter·위/아래 화살표는 행을 이동하고 마지막 붙여넣기는 되돌릴 수 있습니다. 빈 행은 저장되지 않으며 최대 2,000명을 지원합니다. 선택한 행의 하단 상세에서 국가·선호 언어·대상별 URL·별도 수신번호와 연락채널을 수정하며 표와 함께 갱신됩니다. 기본 휴대전화는 문자·카카오 공통 번호로 연결합니다. Excel·CSV 파일 가져오기는 별도로 유지하며 발송 체크를 해제한 대상자는 전송에서 제외됩니다.
3. STEP 02에서 일괄·개별 발송 범위, 채널·발신 정보와 문안을 선택합니다. `{{name}}`, `{{surveyTitle}}`, `{{surveyUrl}}`, `{{closingDate}}`를 문안 안에 넣을 수 있습니다. 카카오는 SOLAPI 승인 기본형 템플릿을 선택하고 변수를 연결합니다.
4. 일괄 발송의 대상별 치환 확인은 접어서 제공하며 발송 명단을 변경하지 않습니다. 개별 발송은 검색한 한 사람의 전화번호·이메일을 선택해 실제 치환된 이름·문안·링크·카카오 버튼을 확인합니다. 입력 변경 시 서버 미리보기를 갱신하며 그 전에는 발송할 수 없습니다. 이메일 HTML은 스크립트·외부 추적 요청을 차단한 격리 화면에 표시합니다. 수신 앱별 글꼴·줄바꿈은 다를 수 있습니다.
5. 왼쪽 발송 설정에서 즉시 또는 예약 시각(브라우저 현지 시간대 표시)을 정하고 수신 동의 확인 후 발송을 요청합니다. 예약은 SOLAPI 예약 접수 기능을 사용합니다. 미리보기·대상자 선택·단계 이동으로 저장하거나 발송하지 않습니다. 우선 채널 한 개 방식은 비동기 실패 자동 대체를 뜻하지 않습니다.

Oracle의 기존 PLAN_JSON·ATTRIBUTES_JSON·MESSAGE_TEMPLATE_JSON 및 발송 상태 열을 사용하므로 이번 변경에 DDL/ALT 실행은 필요하지 않습니다. 연락처는 별도 암호화 열에 보관하며 메시지 JSON에 원본 수신번호를 복제하지 않습니다. 발송은 QUEUED 행을 SENDING으로 선점·커밋한 후 DB 트랜잭션 밖에서 수행합니다. provider_message_id가 있는 SENDING은 **접수**이며 수신 완료를 뜻하지 않습니다. 타임아웃이나 프로세스 중단으로 접수 여부가 불명확하면 확인 필요로 남기고 자동 재전송하지 않습니다. 화면의 미요청 작업 이어하기는 아직 QUEUED인 행만 처리합니다. 전송·예약의 최종 상태와 접수 실패 상세는 SOLAPI 콘솔에서 확인합니다. 실패·확인 필요 건의 자동 재발송과 최종 수신 웹훅은 제공하지 않습니다.

문자 본문은 UTF-8 JSON으로 전송하며 설문 링크는 쿼리 값만 한 번 인코딩합니다. 전체 URL을 재인코딩하지 않습니다. 국내 문자는 대상별 치환 후 EUC-KR 바이트 수로 90바이트 이하 SMS, 초과 LMS(최대 2,000바이트)를 명시하고 미리보기에 종류·용량을 표시합니다. URL 포함 실패는 인코딩 오류로 단정하지 않고 발송 이력의 반환 코드를 확인합니다.

공식 계약: [HMAC 인증](https://solapi.com/developers/api/authentication-api-key), [메시지 발송·예약](https://solapi.com/developers/api/messages), [발송 가능한 알림톡 템플릿](https://solapi.com/developers/api/templates-getTemplateList-getSendableTemplates).

가짜 대상자와 가짜 SOLAPI 응답으로 검증합니다. 자동화 검증은 실제 키 유효성·발신번호 인증·승인 템플릿·잔액·실제 수신을 확인한 것으로 해석하지 않습니다.


### 발송 이력과 SOLAPI 반환 메시지

배포 센터 하단 **발송 이력·요청 결과**에서 조회 버튼을 누르면 과거 버전·이전 배포 작업과 종료된 설문의 이력도 조회합니다. 프로젝트·처리 결과로 필터하고 50건씩 이동할 수 있습니다. 즉시 발송 결과와 이력 모두 반환 코드·설명, 요청/반환 시각, 작업 ID, SOLAPI 메시지·그룹 ID를 제공합니다. 접수 상태는 수신 완료가 아니며 최종 통신사 전송 상태는 SOLAPI 콘솔에서 확인합니다.

발신번호는 저장된 배포 초안의 값을 우선합니다. 환경변수 `SURVEYONE_SOLAPI_DEFAULT_SENDER`는 서버 시작 시 읽으므로 변경 후 서버를 재시작해야 하며, Render는 운영 Environment에서 변경·재배포해야 합니다. 편집 중인 초안의 **기본값** 버튼은 서버 기본번호를 다시 조회해 적용하고 미리보기·동의를 무효화합니다. 발송 후에도 대상자·채널·문안·발신번호를 같은 화면에서 직접 수정합니다. 이전 요청·예약과 이력은 그대로 두고, 수정 후 저장·발송 시 별도 배포 작업을 생성합니다. 수정 없이 단순 조회하는 것만으로는 재발송할 수 없으며 변경 후에는 미리보기·동의를 다시 확인합니다. 기본값 조회가 실패하면 기존 작업을 그대로 유지합니다.

발송 요청 후에는 하단 이력을 자동으로 펼치고 현재 프로젝트·전체 결과로 조회합니다. 요청 요약·실패 코드와 반환 메시지를 이력 위에 표시하며 이번 요청 상세는 펼쳐서 확인합니다. 결과 재확인은 이력도 갱신하고, 상단 편집 공간의 높이를 줄이지 않습니다.

현재 사용자의 일일 50건 사용 기준을 검토 화면에 안내합니다. 이는 SOLAPI의 공통 무료 요금제나 남은 할당량을 보증하는 표시가 아닙니다. 문자와 카카오를 함께 선택하면 채널별로 요청되며, 계정의 다른 발송량까지 합친 실제 한도는 SOLAPI가 판정합니다. HTTP 오류의 errorCode/errorMessage와 개별 메시지의 statusCode/statusMessage를 받아 한도 초과·인증·발신번호 등 반환 사유를 표시합니다. 이 기능은 50건을 앱에서 강제로 제한하거나 잔여량을 조회하는 기능은 아닙니다.

기존 INIT$SVY_TB_DELIVERY의 상태·메시지 ID·시각 및 MESSAGE_TEMPLATE_JSON.deliveryResult에 정제한 반환 코드·설명·그룹 ID·요청/수신 시각을 보존합니다. 새 배포나 서버 재시작으로 기존 Oracle 기록을 덮어쓰지 않습니다. 새 테이블·컬럼은 필요하지 않아 DDL/ALT 실행이 없으며 database/deployments.sql의 DELIVERY_HISTORY_BY_OWNER 및 결과 저장 쿼리를 사용합니다. 과거 버전 조회도 tenant와 현재 프로젝트 소유권을 검증하며, 응답 JSON 전체·인증 헤더·원본 연락처를 반환 로그에 저장하지 않습니다. 기록은 프로젝트 데이터의 삭제·보유 정책을 따릅니다. 기존 작업은 당시 저장된 코드·상태만 표시하며 과거에 보관하지 않은 설명을 복원하지 않습니다.

## 시스템 로그인 정책

기본값은 중복 로그인 허용입니다. 플랫폼 관리자는 시스템 환경 설정(M06001)의 로그인 정책에서 `중복 로그인 허용`을 변경하고 `로그인 정책 저장`으로 서버에 저장합니다. 전체 계정에 공통 적용하며 일반 사용자는 변경할 수 없습니다. 브라우저 작업 환경 기본값과 별개이며 `.env`에 추가할 항목은 없습니다.

허용 시 여러 기기·브라우저에서 로그인 상태를 유지합니다. 해제하면 다음 로그인 성공 시 해당 계정의 이전 세션만 종료하고 새 세션을 유지합니다. 저장 직후 기존 접속을 일괄 종료하지 않으며 로그인 실패도 기존 세션을 종료하지 않습니다. 로그아웃은 요청한 세션만 종료합니다. 같은 브라우저의 여러 탭은 세션 쿠키를 공유합니다.

정책은 전역 메타데이터 `INIT$SVY_TB_LOGIN_POLICY`의 단일 AUTH 행에 보관합니다. 기본 행은 허용으로 최초 생성하며 DDL/ALT 재실행으로 기존 선택을 덮어쓰지 않습니다. 수정 revision으로 관리자 간 덮어쓰기를 막고 Oracle 행 잠금과 트랜잭션으로 정책 변경·세션 교체를 직렬화합니다. 정책 조회 오류 시 memory나 기본 허용으로 우회하지 않습니다.

신규 설치는 SYSTEM_DDL, 기존 설치는 SYSTEM_ALT를 적용합니다. 이 기능의 새 테이블만 추가하려면 다음 명령을 사용합니다. 스크립트는 작업 폴더와 무관하게 자체 위치에서 루트를 계산하고 연결 정보·사용자·세션 값을 출력하지 않습니다.

```powershell
.\venv\Scripts\python.exe -B -X utf8 scripts/apply-login-policy-schema.py
.\venv\Scripts\python.exe -B -X utf8 scripts/apply-login-policy-schema.py --apply
```

첫 명령은 조회만 수행합니다. `--apply`는 누락된 정책 테이블·인덱스·기본 행만 추가하며 기존 정책·계정·세션을 변경하지 않습니다. DB 반영 후 변경 소스를 배포해야 설정 메뉴와 제한 동작이 활성화됩니다.

## 장애 안내와 재시도

공통 API는 기본 30초, 화면 자산은 각각 15초, 화면 준비 전체는 45초, Excel/PDF 다운로드 요청·본문 수신은 각각 120초로 대기 시간을 제한합니다. 제한 시간은 `frontend/config/app.config.js`의 `requestTimeoutMs`, `assetTimeoutMs`, `pageInitTimeoutMs`, `downloadTimeoutMs`로 관리합니다. 정상적인 메뉴 이동 취소는 장애로 표시하지 않습니다.

DB 장애·서버 장애·오프라인·네트워크 연결 실패·응답 시간 초과·잘못된 응답·화면 파일 실패를 공통 전용 안내 화면으로 구분합니다. 초기 세션 조회가 장애로 실패하면 로그아웃이나 비회원 진입으로 해석하지 않고 기존 주소를 유지한 채 재시도하게 합니다. 화면 초기화 중 필수 API의 장애가 개별 모듈에서 처리되어도 로딩 표시나 불완전한 업무 화면만 남기지 않습니다.

업무 중 장애는 현재 DOM과 편집 모듈을 유지하는 전용 안내 레이어로 표시합니다. 작업 복귀는 입력을 보존하고, 화면 다시 불러오기는 기존 `beforeRefresh` 확인을 거칩니다. 저장·발송 요청의 응답이 불명확하면 처리 여부를 단정하지 않으며 자동으로 재요청하지 않습니다. 공개 설문도 최초 조회는 재시도 안내, 제출 실패는 답변과 같은 idempotency key를 유지합니다.

독립 안내 문서는 `/error` 또는 `/frontend/error.html`입니다. 복귀 주소는 동일 origin의 화면만 허용하고 API 주소로 이동하거나 POST를 재생하지 않습니다. 서버는 DB/서버/타임아웃 오류를 안전한 한국어 설명·오류 코드·무작위 문의 번호로 반환하고 로그에는 문의 번호·분류·예외 유형만 남깁니다. Oracle 연결 문자열이나 예외 원문·사용자 입력은 표시·기록하지 않습니다. 장애 화면은 DB에 의존하지 않습니다.

브라우저가 최초 HTML이나 공통 JavaScript를 받기 전 서버·호스팅 전체가 중단된 경우에는 브라우저 또는 호스팅의 오류 화면이 표시될 수 있습니다. 이미 열린 앱의 요청 장애와 서버가 응답 가능한 장애는 위 공통 안내를 사용합니다. Oracle 시작 실패는 기존대로 시작을 중단하며 memory로 전환하지 않습니다.


## 배포 버전

관리 화면 왼쪽 상단 로고 아래에서 실제 서버의 배포 버전을 확인합니다. `VERSION`이 기준이며 `/api/version`과 FastAPI 문서도 같은 값을 제공합니다. 버전 조회는 DB를 사용하지 않고 캐시하지 않습니다. 오래 열린 탭은 다시 활성화할 때 1분 간격으로 확인하며 화면과 서버 버전이 다르면 화살표·표시 색과 설명으로 안내합니다. 편집 중 자동 새로고침은 하지 않습니다.

```powershell
# 오늘 날짜의 다음 번호로 갱신 (예: 2026.10.23.14)
.\scripts\set-version.ps1
# 특정 버전을 지정
.\scripts\set-version.ps1 -Version 2026.10.24.1
```

명령은 호출한 폴더와 무관하게 스크립트 위치의 프로젝트를 갱신합니다. `VERSION`, 관리자·공개 HTML과 `app.config.js`의 정적 자산 버전을 함께 변경하며 Git 게시나 서버 재시작은 수행하지 않습니다. 서버를 재시작하거나 변경 소스를 배포해야 표시가 적용됩니다. 버전 조회 실패는 업무를 막지 않고 `버전 확인 불가`로 표시합니다.
